## Proposed classes and required decisions

- **PUBLIC proposal:** intended anonymous interface, subject to owner approval and abuse/privacy tests. Public intake can still write private tenant data.
- **API-key proof:** requires two real synthetic key principals and exact organization/legal-employer binding, not session-table substitution.
- **Signature/replay proof:** provider signature or callback-token verification plus stored resource binding, duplicates and unchanged foreign state. Xendit uses a callback token; it is not an HMAC signature.
- **Token/protocol proof:** invitation, verification, OIDC or bootstrap authority; do not mislabel these as provider signatures.
- **Privileged operations proof:** separately authenticated cross-tenant service authority. Not public merely because no employer session is used.
- **No tenant records proposal:** no employer-record response, but infrastructure/security-state protection can still be required.

The last three classes refine the proposed four-bucket plan: calling privileged global jobs public, or calling invitation tokens webhook signatures, would conceal the actual boundary. **Owner sign-off is pending for every row**, including apparently static public metadata. Source links identify the handler declaration; the notes identify downstream gates that must be exercised.

## Helper evidence and limits

Invitation lookup hashes the token and requires unused/unexpired state in [tokens.ts](../../src/lib/tokens.ts#L28). OIDC callback exchanges the code and verifies issuer/client/nonce before checking domain/membership; no external exchange was attempted. Journal authorization chains [api-v1-extended.ts](../../src/lib/api-v1-extended.ts#L7) into the existing scoped-key guard and the handler explicitly filters organization and legal entity.

Resend's [stored-message update](../../src/lib/mailer.ts#L515) derives audit organization from the matched outbox record. Its bounded historical duplicate lookup is source evidence, not an executed concurrent replay guarantee. PayMongo and Xendit require actual synthetic signed/token-authenticated inbound HTTP tests, durable duplicate checks and unchanged foreign DB/audit snapshots before any credit.

[Operational readiness](../../src/lib/operational-readiness.ts#L28) reads global user, mail, billing and audit aggregates; these endpoints cannot be called tenant-free just because the response is summarized. [Marketing lead capture](../../src/lib/marketing-leads.ts#L35) persists private prospect fields without an organization key; “public intake” describes request access, not public access to stored leads.
