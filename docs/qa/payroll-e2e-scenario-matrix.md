## Independent calculation conventions (not copied from engine output)

Currency PHP, positive earning lines / negative deduction lines. For manual work here: round each *earnings bucket* to the nearest centavo before adding buckets. Integer cents are the comparison unit; do not round only the aggregate or silently discard a liability. `monthly`, `daily`, `hourly` are the three configured pay bases. "Semi-monthly" is a *pay period*, not a fourth employee pay basis. Use first cutoff 2026-10-01..15 and second cutoff 2026-10-16..31 unless stated otherwise; fixed monthly base = monthly basic / 2, divided by calendar days inside a cutoff if employment or effective-dated rate begins partway through. Daily and hourly staff earn for payable worked hours; their fixed monthly PhilHealth basic equivalent depends on governed workday divisor **NEEDS-RULING**. Examples using SSS/PhilHealth/HDMF/BIR estimates are **UNVERIFIED RATE** and test implementation consistency *only*.

ER-only liabilities 1,100 + 15 + 275 + 100 = **1,490.00**, never a payslip deduction. Combined illustrative remittance liabilities = 925 + 1,490 = **2,415.00**. Journal from released run: DR payroll expense 11,000; CR deductions control 925; CR net-pay payable 10,075; DR=CR=11,000. These do *not* authorize statutory filing or release.

## Cross-layer assertions (must be proved against persisted records, not implied by formulas)

1. Every employee's integer-centavo **gross - actually applied deductions = nonnegative net**; all positive earning / negative applied deduction lines reconcile to printed payslip, entry and run totals.
2. For each **released** run, journal DR = CR and DR payroll expense = sum of employee gross; net payable = sum of net; deductions control = gross minus net. Employer-only statutory costs must not reduce payslip net; compare employee+employer contribution totals to *generated internal remittance output* only, not agency acceptance.
3. Replay with same input/period gives identical monetary and line-item bytes (ignore generated IDs/timestamps, which must instead remain single-row unique). Repeating queue processing must not append rows. Mutating a finalized run must fail visibly; adjustments require separate provenance.
4. Two employers on the same date/period must not change one another's persisted entries, remittance snapshots, journal or payslip content.
5. Seeded runs of 50+ fictional workers should use integer cents in the independent oracle, exercise half-cent boundaries and produce stable reproduction details. **Do not simply set an expectation equal to engine output.**
