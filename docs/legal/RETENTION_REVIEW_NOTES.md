## Scheduler: what the code does, and what it does **not** prove

- [ ] **TODO-LEGAL / operations — activation:** [.env.local.example](../../.env.local.example) sets `CENTRAL_SCHEDULER_ENABLED=false`; [worker example](../../deploy/scheduler/worker.env.example) also defaults to false. [src/lib/scheduler-activation.ts](../../src/lib/scheduler-activation.ts) gates scheduler execution independently from `WORKER_ENABLED`. [src/lib/scheduler.ts](../../src/lib/scheduler.ts) exits before work when disabled. **No purge cadence can be promised without deployment-specific evidence.**
- [ ] **TODO-LEGAL / operations — trigger and preconditions:** [POST /api/jobs/tick](../../src/app/api/jobs/tick/route.ts) authenticates an operator/worker and checks worker health; [GET /api/jobs/cron](../../src/app/api/jobs/cron/route.ts) authenticates the cron caller, checks the same scheduler flag and worker health. A configured cron path or worker does **not** prove a scheduler is enabled, regularly invoked or successful.
- [ ] **TODO-LEGAL / operations — actual cadence and monitoring:** [scheduler.ts](../../src/lib/scheduler.ts) uses a fenced lease, a ≥30-second delivery-drain interval unless forced, and a `retention-purge` last-run marker due when absent or ≥24 hours old. The code **checks due work on each eligible tick**; this is not proof of daily ticks. Confirm protected worker, [status endpoint](../../src/app/api/jobs/status/route.ts), receipts, alarms and failures on the real deployment.
- [ ] **TODO-LEGAL / operations — partial failures:** [purgeExpiredOperationalData](../../src/lib/data-retention.ts) attempts multiple steps independently and raises `RetentionPurgeIncompleteError` when any fail. [scheduler.ts](../../src/lib/scheduler.ts) attempts other jobs, records errors and advances the retention marker only when retention/punch purge steps succeed. Inspect real logs and data; don't imply full deletion when partial failures are present.
- [ ] **TODO-LEGAL / operations — other related purge paths:** In addition to the seven operational rows in the policy table, `purgeExpiredOperationalData` calls [rejected applicant cleanup](../../src/lib/recruitment-applicant-retention.ts), [pending COE object recovery](../../src/lib/hr-case-coe-object-reconciliation.ts), [pending spend receipt recovery](../../src/lib/spend-receipt-object-reconciliation.ts) and [pending employee-vault object recovery](../../src/lib/employee-vault-object-reconciliation.ts). [scheduler.ts](../../src/lib/scheduler.ts) also drains [expired workforce punch-photo evidence](../../src/lib/workforce-punch-retention.ts) when that optional table exists, even if new image collection is disabled. Reconcile these additional classes into the notice/ROPA where actually enabled.
