# Security Policy

## Supported versions

| Code line | Security support |
| --- | --- |
| `main` (default branch) | Supported |
| Other branches, tags, and historical snapshots | Not supported |

This policy does not announce a release or a supported version number.

## Scope

Reports are in scope for the PayrollPH/Linaw application, including the Next.js user-facing application, server-side application logic, and its HTTP API routes (`src/app/api/`). Issues in integrated third-party services may require separate disclosure to their operators.

## Reporting a vulnerability

**Private disclosure contact: TODO-OWNER**

The repository owner must replace `TODO-OWNER` with a working private contact or approved private-reporting channel before this policy is operational. Do **not** publish exploit details, personal information, credentials, or financial data in a public GitHub issue.

When a private channel is available, include the affected component or route, impact, reproduction steps or a proof of concept using synthetic data, and a way to follow up. Do not test against real payroll/customer data without authorization.

## Response expectations

**Acknowledgement target: within 48 hours after receipt** of a report through the designated private channel. This is a target, not a guarantee of triage completion, remediation, or disclosure timing.

Remediation and any coordinated disclosure timeline will be assessed case by case.
